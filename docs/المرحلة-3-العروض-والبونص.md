## 1) ما تم بناءه

### أ) العروض الترويجية (3 صفحات)
- **`/director/promotional-offers` — صفحة العرض:** جدول بكل العروض مع البحث، ويعرض: الصنف، قيمة العرض (نسبة خصم أو سعر خاص)، الفترة، المحافظة، والحالة (نشط / قادم / منتهي / موقوف). من كل صف يمكن **تعديل / إيقاف-تفعيل / حذف**.
- **`/director/promotional-offers/new` — صفحة الإنشاء:** نموذج يضم بحثاً وتحديداً للصنف من المنتجات النشطة، ونسبة خصم **أو** سعر خاص (واحد فقط)، وفترة (بداية/نهاية)، ومحافظة اختيارية. عند الإنشاء يُرسل **إشعار تلقائي** للعملاء عبر جدول `notifications`.
- **`/director/promotional-offers/:id/edit` — صفحة التعديل:** تعديل أي عرض موجود (مع عرض النص الأصلي للعروض القادمة من تطبيق Flutter).
- **إدارة سريعة:** صفحتا الإنشاء والتعديل تعرضان لوحة "إدارة سريعة" أسفل النموذج لإيقاف/حذف/تعديل أي عرض دون مغادرة الصفحة (كما طُلب).

### ب) نظام البونص (4 صفحات — بنفس منطق العروض)
- **`/director/bonus-overview` — نظرة عامة:** بطاقات ملخص (إجمالي القواعد، السارية الآن، الموقوفة/المنتهية، القواعد العامة السارية) + جدول "قواعد سارية الآن".
- **`/director/bonus-rules` — القائمة:** جدول بقواعد "اشترِ X واحصل على Y مجاناً" مع البحث، وحالة كل قاعدة، وإجراءات تعديل/إيقاف/حذف.
- **`/director/bonus-rules/new` — الإنشاء:** صنف اختياري (فارغ = قاعدة عامة لكل الأصناف)، كمية الشراء، الكمية المجانية، خيار "قابلة للتراكم" (`is_stackable`)، فترة اختيارية، محافظة اختيارية، + إشعار تلقائي عند الإنشاء.
- **`/director/bonus-rules/:id/edit` — التعديل** + لوحة إدارة سريعة أسفل النموذج.

### ج) عناصر مشتركة
- مكوّن `ProductSearch`: بحث بالاسم العربي/الإنجليزي مع اختيار من قائمة منسدلة، ودعم "جميع الأصناف" في البونص.
- `ConfirmDialog` مألوف لحذف/إيقاف/تفعيل (نفس مكوّنات المراحل السابقة).
- مساران جديدان في القائمة الجانبية للمدير العام: "العروض الترويجية" (أيقونة `BadgePercent`) و"نظام البونص" (أيقونة `Gift`).

## 4) القرارات التقنية

1. **الإشعار التلقائي:** عند إنشاء عرض/قاعدة بونص يُدخَل صف في `notifications` بـ `target_role='client'`؛ وإذا اختيرت محافظة تُحدَّد `target_branch_id` تلقائياً من أول فرع يطابقها (كموجّه إقليمي)، وإلا تُترك فارغة لكل العملاء.
2. **الحذف:** يُحذف الإشعار المرتبط (`related_offer_id`) أولاً ثم العرض، لتفادي تعارض مفاتيح خارجية.
3. **الأصناف غير النشطة:** عند تعديل عرض/قاعدة لصنف موقوف، يُضاف الصنف الحالي إلى قائمة البحث كخيار حتى لا تتعطل عملية التعديل.
4. **حالة العرض/القاعدة:** تُشتق في الواجهة من `is_active` + `start_date`/`end_date` (نشط/قادم/منتهي/موقوف) دون RPC.
5. **التسميات والألوان** مطابقة لشاشات المراحل السابقة (emerald/amber/blue/violet، `bg-card border rounded-xl shadow-sm`).

## 5) تعديلات قاعدة البيانات (مطلوب تنفيذها)

ملف **`supabase/migrations/0003_phase3_offer_product_discount_columns.sql`** يضيف:
1. الأعمدة الثلاثة الناقصة في `promotional_offers` (`product_id`, `discount_percent`, `special_price`).
2. سياسات RLS تضمن للمدير العام (دور `company_director`) القراءة/الإدراج/التحديث/الحذف على `promotional_offers` و`bonus_rules` (سياسات تراكمية لا تمسّ سياسات Flutter الحالية).

> **تنفيذ الخطوة (يدوي — مرة واحدة):** من Supabase Dashboard → SQL Editor، الصق محتوى الملف وشغّله. (CLI غير مرتبط بالمشروع ولا يتوفر كلمة مرور قاعدة البيانات.)
> جدول `notifications` يسمح بالإدراج أصلاً (تحقق حي: 201 OK) فلا حاجة لسياسات له.

## 7) خطوات التشغيل بعد الرفع

1. شغّل `supabase/migrations/0003_phase3_offer_product_discount_columns.sql` من SQL Editor.
2. `pnpm --filter @workspace/pharma-pwa run dev` ثم سجّل الدخول بحساب مدير عام.
3. جرب: عروض → إضافة عرض (لاحظ الإشعار) → إيقاف/تعديل/حذف، ثم بونص → نظرة عامة → إنشاء قاعدة → إدارة سريعة.
