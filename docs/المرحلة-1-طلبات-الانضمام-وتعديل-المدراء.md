## 1) ما تم بناءه

### أ) شاشة "طلبات الانضمام المعلّقة" (جديدة)
- تستعلم `users` حيث `role='client'` و `account_status='pending_approval'`.
- جدول يعرض: اسم المنشأة (+البريد)، النوع، الهاتف، المحافظة/المدينة، تاريخ التسجيل.
- زرّان لكل صف: **قبول** (يحوّل `account_status` إلى `active`) و**رفض** (إلى `rejected`)، مع نافذة تأكيد (`ConfirmDialog`).
- رابط "طلبات الانضمام" في القائمة الجانبية بجانب "مدراء الفروع" (أيقونة `UserCheck`).

### ب) توسيع شاشة "مدراء الفروع" للتعديل
- زر **"تعديل"** لكل صف يفتح نموذجاً معبّأً بالبيانات الحالية (الاسم، الهاتف، الفرع، البريد للقراءة فقط).
- أزرار **إيقاف/تفعيل** نصّية واضحة (بديلاً عن الأيقونات الصامتة) تعمل بنفس تدفق التأكيد السابق، وتنتقل بين `active` و `suspended`.
- (الزر الجديد الوحيد على الخادم: `update_profile` — راجع §3).

## 3) القرارات التقنية

1. **الكتابة عبر Edge Function فقط، وليس عبر الـ client مباشرة** — نفس نمط `manage-branch-manager-account` الحالي:
   - التحقق من JWT عبر `auth.getUser()`.
   - التحقق من أن المتصل `company_director` نشط (`role` + `account_status='active'`).
   - التحقق من أن الهدف `branch_manager` (أو `client` في دالة العملاء) قبل أي تعديل.
   - التحديث عبر مفتاح الخدمة.
2. **`update_profile` يحدّث `name/phone/branch_id` (+ `branch_name` المشتق من جدول `branches`)**، ويزامن `user_metadata` في `auth.users` حتى ترى تطبيقات Flutter نفس القيم.
3. **`account_status` هو مصدر الحقيقة للحالة** (قيمة موجودة فعلاً من migration 0003 في مشروع Flutter الأصلي: `pending_approval/active/rejected/suspended`).
4. **استعلام المعلّقين بـ `select('*')` + تعيين دفاعي** للأعمدة الاختيارية (`org_name`, `client_type`, `city`, `governorate`) — هذه الأعمدة غير مضمونة الوجود في كل البيئات، فالكود يقبل غيابها ولا يكسر الصفحة.
5. **لا يوجد أي تعديل على مخطط قاعدة البيانات** في هذه المرحلة — كل الحقول المستخدمة (`role`, `account_status`, `branch_id`, `branch_name`) موجودة مسبقاً من migrations 0001/0003. ولا حاجة لأي migration جديد (بند الاستكمال رقم 2 من الطلب).

## 4) النشر والتحقق

```bash
supabase functions deploy manage-branch-manager-account --project-ref lmkomzqioneuyvatzsov
supabase functions deploy manage-client-account          --project-ref lmkomzqioneuyvatzsov
```

**النتيجة (فُحصت بـ `supabase functions list`):** الدالتان `ACTIVE` مع `verify_jwt: true`:
- `manage-branch-manager-account` → **version 2** (يتضمن `update_profile`).
- `manage-client-account` → **version 1**.

الواجهة: typecheck نظيف، الصفحتان تُحمَّلان على الخادم المحلي (HTTP 200).
