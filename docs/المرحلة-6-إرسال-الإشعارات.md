## 2) ما تم بناؤه

### أ) Migration: `supabase/migrations/0005_flexible_notification_targeting.sql`
- إضافة عمود `target_user_ids uuid[] NOT NULL DEFAULT '{}'` لجدول `notifications`.
- إعادة إنشاء سياسة `notifications_select_relevant` مع شرط تراكمي إضافي:
  `OR auth.uid() = any(target_user_ids)` (تبقى شروط القراءة الأصلية سليمة لتطبيق Flutter).
- **ملاحظة:** لم يُشغَّل بعد — ينفَّذ من Supabase Dashboard → SQL Editor.

### ب) صفحة "إرسال إشعار" على `/director/send-notification`
- **الخطوة 1:** اختيار الدور المستهدف (عميل / مدير فرع / مندوب).
- **الخطوة 2:** نطاق الإرسال:
  - "الكل ضمن هذا الدور" → سجل `notifications` واحد بـ `target_role` محدداً و `target_user_ids = '{}'`.
  - "مجموعة محددة" / "فرد واحد" → قائمة بحث متعددة الاختيار (اسم المستخدم + الفرع + الهاتف) تُحلّ من `public.users` حسب الدور، مع تحقق: مجموعة ≥ 1، فرد = 1 بالضبط. تُرسل كـ **سجل واحد** بـ `target_role = null` و `target_user_ids = [المعرّفات المختارة]`.
- **الخطوة 3:** عنوان + نص الإشعار وزر الإرسال (مع `created_by = المدير`).
- **سجل أسفل الصفحة:** آخر 20 إشعاراً مرسلاً يعرض لكل واحد: النطاق (الكل / عدد محدد)، الدور، العنوان، التاريخ.

### ج) واجهة API: `src/lib/sendNotificationApi.ts`
- `listUsersByRole(role)`، `sendNotification(...)`، `listSentNotifications(limit)`.

### د) توحيد المصطلحات: "سائق" → "مندوب" (نصوص عرض فقط)
تغيير نصي فقط — **لا** تغيير في قيمة الدور `'driver'` بقاعدة البيانات ولا في أي منطق يعتمد عليها:

| الملف | التغيير |

| `src/pages/director/DriversPage.tsx` | كل نصوص "السائق/السائقين/سائقو" → "المندوب/المندوبين/مندوبو" (9 مواضع) |
| `src/layouts/DirectorLayout.tsx` | عنوان الصفحة واسم القائمة الجانبية "السائقون" → "المندوبون" (2 موضع) |
| `src/pages/director/SendNotificationPage.tsx` (جديد) | يستخدم "مندوب" منذ البداية |
