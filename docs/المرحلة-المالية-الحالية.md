# المرحلة المالية — الدفعة الحالية

## الأساس المعتمد
هذه الدفعة مبنية على `main` الحالي، وليس على نسخة قديمة من المشروع. آخر تصميم في المشروع يعتمد العربية وRTL ووضع القيادة التنفيذي الداكن، لذلك يجب أن تتبع صفحات المالية نفس `director-panel` و`director-reveal` ونظام الألوان الحالي، دون إنشاء Theme مستقل.

## قاعدة البيانات
أضيفت migrations المالية التالية:
- `0006_financial_core.sql`: الشركات، العملات، أسعار الصرف، السنوات والفترات، مراكز التكلفة، دليل الحسابات، الصناديق، البنوك، المستندات المالية، القيود اليومية، تفاصيل القيود، الترحيل المتوازن، وسجل التدقيق.
- `0007_financial_receivables_control.sql`: سندات القبض، الدفعات الجزئية، منع تجاوز قيمة الفاتورة، وربط التخصيصات.
- `0008_financial_cash_bank_controls.sql`: حركات الصناديق والبنوك، التحويلات، والمطابقة البنكية.
- `0009_financial_inventory_accounting.sql`: حركات المخزون، الجرد، وتسويات المخزون وربط حسابات المخزون والتكلفة.
- `0010_financial_expenses_assets_budgeting.sql`: المصروفات، الأصول الثابتة، الإهلاك، والموازنات.
- `0011_financial_reporting.sql`: دفتر الأستاذ، ميزان المراجعة، ربحية الفروع، أرصدة العملاء، وملخص الصناديق والبنوك.

## قواعد محاسبية
1. القيد المزدوج إلزامي: المدين = الدائن.
2. لا يرحّل قيد إلى فترة مغلقة.
3. القيد المرحّل لا يُحذف أو يُعدل بصمت؛ التصحيح يكون بعكس أو قيد تصحيحي.
4. حالة الفاتورة لا تعتبر وحدها دليلاً على القبض.
5. الدفعات الجزئية مدعومة.
6. تجاوز رصيد الفاتورة بالدفعات ممنوع.
7. كل حركة مالية قابلة للربط بمستند ومستخدم.
8. RLS هي طبقة الحماية الأساسية، وليس إخفاء عناصر الواجهة.

## العلاقة مع النظام الحالي
لا يتم استبدال `invoices`, `payments`, `warehouse_inventory`, `users`, `branches`, `products`. النظام المالي يضيف طبقة محاسبية مركزية فوق هذه الكيانات.

## ملاحظة تنفيذية
لم يتم اعتبار هذه الدفعة مكتملة الإنتاج بمجرد إنشاء الملفات؛ يجب تطبيق migrations على بيئة Supabase التطويرية، ثم اختبار SQL وRLS ودورة الفاتورة/التحصيل والجرد والمطابقة قبل الدمج إلى `main`.
