# حالة تسليم النظام المالي — مراجعة نهائية قبل الإنتاج

## الحالة الحالية
الفرع: `financial/release-candidate`

هذا الفرع متقدم عن `main` بسبعة commits، وآخر نقطة أساس لـ`main` هي commit التصميم الجديد، بينما تغييرات المالية موجودة على الفرع المالي. لا يوجد GitHub Actions run لهذا الفرع حتى تاريخ هذه المراجعة.

## ما تم بناؤه في الكود
- نواة محاسبية موحدة.
- العملات والشركات والسنوات والفترات.
- دليل الحسابات ومراكز التكلفة.
- القيود اليومية وتفاصيلها والتحقق من التوازن.
- دفتر الأستاذ وميزان المراجعة.
- الفواتير والذمم والتحصيل كطبقة مرتبطة بالنظام التشغيلي.
- الموردون وفواتير الموردين والمدفوعات.
- الصناديق والحسابات البنكية والحركات.
- المطابقة البنكية كأساس.
- حركات المخزون والجرد والتسويات كأساس مالي.
- المصروفات والأصول والموازنات كأساس.
- سجل التدقيق وقيود عدم تعديل القيود المرحّلة.
- RLS/حماية مالية ضمن الـmigrations.
- واجهة مالية متناسقة مع التصميم الجديد.

## ما لا يجوز اعتباره منجزاً تلقائياً
وجود SQL في GitHub لا يعني أن قاعدة Supabase الإنتاجية طبقت هذه الـmigrations أو أن اختبارات التكامل مرت بنجاح. كما أن GitHub Actions لا يحتوي حالياً على runs لهذا الفرع.

## المطلوب قبل الإنتاج
1. تشغيل الـmigrations على بيئة Supabase تطويرية/نسخة اختبارية.
2. تنفيذ اختبارات SQL للتوازن، الفترات المغلقة، RLS، وعدم تعديل القيود المرحّلة.
3. اختبار دورة: فاتورة عميل → ذمة → قبض → قيد → دفتر أستاذ.
4. اختبار: فاتورة مورد → ذمة دائنة → دفع → قيد.
5. اختبار: مخزون → بيع/تسوية → أثر التكلفة.
6. اختبار الصناديق والبنوك والتحويلات والمطابقة.
7. تشغيل typecheck/build للمشروع بعد تطبيق التغييرات.
8. مراجعة نتائج الاختبارات قبل دمج الفرع إلى `main`.
9. تطبيق migrations على Production فقط بعد أخذ نسخة احتياطية واعتماد نتيجة الاختبارات.

## قرار التسليم
النظام المالي **ليس جاهزاً للإنتاج النهائي بعد** رغم اكتمال مساحة كبيرة من البنية والواجهات؛ السبب هو عدم وجود إثبات من بيئة تشغيلية بأن migrations اختبرت وتطبقت بنجاح، وعدم وجود CI run لهذا الفرع.

هذه ليست خطوة مطلوبة من المستخدم في التصميم أو البرمجة؛ هي خطوة تشغيلية لا يمكن تنفيذها بأمان من GitHub وحده دون الوصول إلى قاعدة Supabase المستهدفة/بيئة اختبارها.

## قاعدة المشروع
لا يتم دمج الفرع المالي إلى `main` على أنه Production Ready قبل اجتياز هذه القائمة.
